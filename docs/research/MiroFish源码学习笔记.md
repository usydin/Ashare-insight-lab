## MiroFish 项目定位

MiroFish 将自己定位为“群体智能预测引擎”或“多智能体推演沙盒”。

从 README 与目录结构可以看出，它的核心目标不是做传统量化回测，也不是做金融终端，而是：

- 从现实世界输入中抽取种子材料
- 构建人物关系与群体环境
- 让大量 Agent 在模拟环境中互动演化
- 基于推演过程生成报告与交互结果

它更像一个“社会模拟实验室”，适合处理事件传播、叙事扩散、舆情演化、政策冲击等问题。

## 顶层目录结构

从扫描结果看，MiroFish 顶层结构大致如下：

- `backend/`
  - Python 后端，负责 API、图构建、环境配置、模拟运行与报告生成
- `frontend/`
  - Vue 前端，负责五阶段工作流界面
- `locales/`
  - 国际化文案
- `static/`
  - 图片、演示资源
- `Dockerfile` / `docker-compose.yml`
  - 容器化运行方案
- `package.json`
  - Node.js 前端与联合启动脚本

对 A股智研台的启发是：它把“研究流程”而不是“单个模型调用”作为产品主线来组织。

## backend/app/api 的职责

`backend/app/api/` 目录包含三类核心接口：

### `graph.py`

负责图谱构建相关接口，推测主要职责包括：

- 接收种子材料
- 调用图谱构建流程
- 管理图结构与实体关系的生成结果

这说明 MiroFish 的第一步不是直接跑模拟，而是先把“世界结构”搭起来。

### `simulation.py`

负责模拟运行相关接口，推测主要职责包括：

- 创建模拟任务
- 提交模拟配置
- 启动或查询模拟状态
- 管理多轮推演过程

这对应 MiroFish 的核心能力层，是其“社会模拟引擎”的入口。

### `report.py`

负责报告生成与查询接口，推测主要职责包括：

- 汇总模拟结果
- 调用报告 Agent 进行结构化总结
- 输出最终研究报告

这说明其输出不是只有日志，而是把模拟结果沉淀为“可阅读的结论层”。

## backend/app/services 的职责理解

`backend/app/services/` 是 MiroFish 的核心编排层，负责把各个阶段串起来。

### `graph_builder.py`

- 根据输入材料构建实体、关系和图结构
- 为后续环境配置与 Agent 分布提供底层拓扑

### `ontology_generator.py`

- 生成领域本体或概念结构
- 帮助系统理解“有哪些角色、关系、事件类型”

### `oasis_profile_generator.py`

- 生成模拟角色画像
- 为 Agent 提供身份、偏好、行为倾向等设定

从文件名看，它与 OASIS 生态有关，但对 A股智研台而言只借鉴“角色画像生成”思想，不引入其实现。

### `simulation_config_generator.py`

- 生成模拟参数
- 控制 Agent 数量、轮次、环境变量与任务目标

这一步很重要，因为社会模拟的成本和稳定性很大程度由配置决定。

### `simulation_manager.py`

- 负责任务生命周期管理
- 管理模拟创建、调度、状态查询与资源协调

### `simulation_runner.py`

- 真正执行模拟流程
- 推动多轮交互、状态推进和记忆更新

### `report_agent.py`

- 对推演后的世界状态做总结
- 将复杂互动结果转成最终报告、要点、路径和结论

### `zep_tools.py`

- 处理记忆图谱或外部记忆能力相关工具
- 支持从历史交互中读取和更新结构化记忆

对 A股智研台的启发不是引入 Zep，而是认识到“情景推演”通常需要显式记忆层。

## backend/scripts 的用途

扫描结果显示 `backend/scripts/` 下包含多个脚本：

### `run_twitter_simulation.py`

- 用于跑基于 Twitter/X 语境的事件推演
- 适合观察社交传播、舆情扩散和叙事演变

### `run_reddit_simulation.py`

- 用于跑基于 Reddit 社区语境的事件推演
- 适合观察社区讨论、观点极化和群体互动

### `run_parallel_simulation.py`

- 用于并行执行模拟任务
- 可能用于提高效率，或对同一输入做多次独立试验

对 A股智研台而言，这类脚本启发在于：未来可把情景推演做成独立实验任务，而不是塞进日常信号主流程。

## frontend/src/components 的产品流程

前端组件命名很直观，呈现出一个五阶段产品流程：

### `Step1GraphBuild.vue`

- 第一步：Graph Building
- 用户上传种子材料，系统生成实体关系图和基础世界结构

### `Step2EnvSetup.vue`

- 第二步：Environment Setup
- 用户查看和调整环境、角色、配置、推演范围

### `Step3Simulation.vue`

- 第三步：Simulation
- 启动多 Agent 推演，观察运行状态与阶段结果

### `Step4Report.vue`

- 第四步：Report
- 生成情景报告、总结传播路径和可能结论

### `Step5Interaction.vue`

- 第五步：Interaction
- 用户进一步和系统互动，追问个别角色、个别节点或某种路径

这说明 MiroFish 的产品设计重点是“从输入材料到深度交互”的完整闭环，而不是一次性给答案。

## 五阶段流程理解

MiroFish 在 README 中明确给出了五阶段流程：

### 1. Graph Building

- 抽取实体、关系、事件与记忆
- 构建初始 GraphRAG / 世界图谱

### 2. Environment Setup

- 生成角色画像
- 设置群体环境、交互规则与任务目标

### 3. Simulation

- 让多 Agent 在设定环境中并行演化
- 记录叙事变化、观点碰撞和行为路径

### 4. Report Generation

- 汇总推演结果
- 产出面向决策者的结构化报告

### 5. Deep Interaction

- 用户继续追问
- 与角色或报告层做更深交互

对 A股智研台而言，这个五阶段流程最大的价值是：把“情景推演”从单次 LLM 生成升级为一个结构化研究实验流程。

## 对 A股智研台的启发

MiroFish 对 A股智研台最有价值的启发，主要集中在“事件驱动研究”层：

1. 可以把突发公告、政策变化、行业事件视为“情景种子材料”
2. 可以把不同市场参与者建模为不同角色，而不是只有一个研究 Agent
3. 可以输出乐观、中性、悲观三类情景，而不是单一结论
4. 可以记录叙事传播路径、风险触发条件和关键分歧点
5. 可以把情景推演作为 Agent 研究层的一个实验模块，而不是交易信号本身

## 当前结论

如果说 TradingAgents 更像“AI 投研大脑”，FinceptTerminal 更像“金融终端外壳”，那么 MiroFish 更像“情景推演沙盒”。

它适合为 A股智研台未来补上一层：

- 不是预测明天股价
- 而是推演“如果某类事件发生，市场叙事可能如何扩散，风险可能如何累积，哪些路径最值得人工复核”

这层能力当前只做研究规划，不做工程落地。
