# 多智能体投研架构借鉴方案

## 文档定位

本文档用于规划 A股智研台未来可能借鉴的多智能体投研结构，属于架构研究文档，不代表当前已经实现。

当前原则：

- 只研究，不落地源码复制
- 只规划，不引入新依赖
- AI 只做研究建议，不自动实盘下单

## 未来 Agent 层角色设计

### 1. A股技术面分析员

职责：

- 读取日线、均线、成交量等基础技术指标
- 判断趋势、拐点与阶段性强弱
- 输出结构化技术面摘要

### 2. A股公告/财报分析员

职责：

- 读取上市公司公告、财报、业绩预告等文本信息
- 识别利多、利空、异常风险和经营变化
- 提取可用于日报和复盘的结论

### 3. 新闻宏观分析员

职责：

- 跟踪政策、宏观、市场新闻
- 判断消息对大盘与行业的影响方向
- 输出宏观背景和风险提醒

### 4. 行业/板块分析员

职责：

- 观察行业轮动、板块热度和联动关系
- 补充个股之外的中观视角
- 识别板块共振和板块退潮风险

### 5. 看多研究员

职责：

- 站在做多逻辑上整理支持论据
- 聚合技术面、公告、行业与消息面中的利多因素
- 明确上涨逻辑的成立条件

### 6. 看空研究员

职责：

- 站在否定观点上寻找漏洞和风险
- 指出估值、趋势、消息、基本面中的潜在反例
- 防止系统只收集单边利多证据

### 7. 风险审查员

职责：

- 统一审查单只股票和组合层面的风险
- 重点识别波动、流动性、突发事件、数据异常和过度集中问题
- 对研究建议进行否决或降级

### 8. 组合经理

职责：

- 汇总多角色结论
- 给出组合层面的研究建议和优先级排序
- 为未来模拟盘提供“建议配置”而不是自动执行

### 9. 模拟盘复盘员

职责：

- 回看历史建议与模拟盘结果
- 总结哪些研究结论有效，哪些结论失效
- 为后续策略优化提供复盘输入

## 与当前 run-daily 的关系

当前 `run-daily` 已具备：

- 数据采集
- 技术信号生成
- 日报输出
- 单只股票失败不中断

未来 Agent 层不应替代 `run-daily`，而应建立在其上方：

- `run-daily` 提供基础数据与结构化信号
- Agent 层消费这些结果，生成更高层的研究解读
- 这样可以保持底层稳定、上层可演化

## 与 doctor 数据源健康检查的关系

当前 `doctor` / `check-data-source` 负责确认：

- 数据源是否可用
- 网络是否正常
- 代理是否影响访问
- 示例股票是否能采集

未来 Agent 层依赖数据源，因此：

- `doctor` 应继续作为 Agent 运行前的基础健康检查
- 如果 doctor 结果为 `failed` 或 `degraded`，应提示谨慎使用 Agent 报告
- Agent 输出应感知“数据源不稳定”这一状态，而不是默认数据总是可靠

## 与未来模拟盘的关系

未来如果引入模拟盘：

- Agent 层可以输出“研究建议”
- 模拟盘层负责“如何记录与执行模拟动作”
- 两者不应混在一起

推荐边界：

- Agent 层：给出研究结论、风险提示、建议仓位方向
- 模拟盘层：记录买卖、仓位、成本、盈亏和复盘

## 与未来 OpenClaw 的关系

OpenClaw 未来应定位为调度层与交互层，而不是 Agent 内核。

推荐关系：

- Python 平台：负责数据、信号、报告、模拟盘等底层核心
- Agent 层：负责多角色研究与汇总
- OpenClaw：负责调度、摘要生成、状态监控、人机交互

因此，OpenClaw 不应该承载：

- 交易执行
- 券商连接
- 实盘自动下单

## AI 只做研究建议，不自动实盘下单

这是本项目的硬边界。

即使未来引入多智能体架构，也仍然坚持：

- AI 只给研究建议
- 不自动实盘交易
- 不自动下单
- 不连接真实券商账户
- 不绕过任何平台限制

## 适配建议

对 A股智研台更现实的路线是：

1. 先把 `run-daily` 和 `doctor` 做稳定
2. 再补强公告、新闻、行业等结构化输入
3. 先实现“多角色报告生成”，不实现复杂图式编排
4. 等模拟盘账本稳定后，再考虑引入“决策记忆”和“多空辩论”

## 当前不落地的内容

当前不落地：

- 不实现 TradingAgents 式完整多智能体框架
- 不引入 LangGraph
- 不引入 LangChain
- 不引入 Backtrader
- 不实现自动化交易执行
- 不实现 OpenClaw 代码
