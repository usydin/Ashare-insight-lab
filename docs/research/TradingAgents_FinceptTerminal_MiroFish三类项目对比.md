# TradingAgents / FinceptTerminal / MiroFish 三类项目对比

## 文档定位

本文档用于对比三类已研究的第三方开源项目，并明确它们各自对 A股智研台的启发边界。

## 三类项目的核心定位

### TradingAgents

- 定位：AI 投研大脑
- 强项：多角色研究流程、结构化输出、决策记忆、风控辩论
- 更关注“如何做研究推理”

### FinceptTerminal

- 定位：金融终端产品外壳
- 强项：页面模块组织、服务层解耦、DataHub、连接器体系、工作台设计
- 更关注“如何组织成产品平台”

### MiroFish

- 定位：情景推演沙盒
- 强项：事件种子输入、多 Agent 社会模拟、五阶段实验流程、情景报告
- 更关注“如果事件扩散，可能会怎么演化”

## 三者分别给 A股智研台带来的启发

### TradingAgents 的启发

- 把投研流程拆成多个专业角色
- 将研究过程结构化
- 引入多空辩论与风控审查
- 为未来决策记忆和复盘提供思路

### FinceptTerminal 的启发

- 用工作台而不是单页面理解未来终端化
- 将页面层与服务层解耦
- 将数据源能力组织成统一入口
- 把报告中心、风控中心、自选中心等模块长期化

### MiroFish 的启发

- 把重大事件研究做成情景推演实验
- 把市场参与者看作不同角色进行推演
- 输出三情景、传播路径和风险触发条件
- 在研究层中增加“叙事传播与事件冲击”视角

## A股智研台长期融合路线

从长期看，三者可以分别补足 A股智研台的不同层级：

- TradingAgents 补“研究大脑”
- FinceptTerminal 补“终端外壳”
- MiroFish 补“情景推演实验室”

更完整的长期组合可以理解为：

1. 底层由 A股本土数据与日报系统提供稳定输入
2. TradingAgents 风格的 Agent 层提供研究分工和风控辩论
3. MiroFish 风格的 Scenario Lab 提供事件传播与情景推演
4. FinceptTerminal 风格的终端化路线提供统一工作台和展示层

## 哪些内容当前只研究不落地

当前明确只研究、不落地的内容包括：

- TradingAgents 风格的完整多 Agent 编排框架
- FinceptTerminal 风格的 GUI、DataHub、原生终端实现
- MiroFish 风格的社会模拟引擎和前后端实验室
- 任意第三方项目的源码、UI、Logo、名称与品牌表达

## 当前版本的实际边界

本项目当前仍然坚持：

- 不复制第三方源码
- 不引入新依赖
- 不做 GUI
- 不做模拟盘代码
- 不做 OpenClaw 代码
- 不做实盘交易
- 不自动下单

因此，三类项目当前都只是“研究对象”，不是“待并入代码”。

## 对 A股智研台的实际建议

现阶段更合理的顺序是：

1. 继续夯实 `run-daily` 与 `doctor`
2. 继续沉淀结构化报告和研究文档
3. 先规划 Agent 层与 Scenario Lab 的边界
4. 未来再视成熟度考虑模拟盘、决策记忆和轻量 GUI

## 当前结论

三类项目并不是互相替代，而是分别回答三个不同问题：

- TradingAgents 回答：研究流程怎么拆
- FinceptTerminal 回答：产品平台怎么搭
- MiroFish 回答：事件情景怎么演

A股智研台的长期路线，是在自有版权体系下，吸收三者的“方法论”，而不是复制三者的“实现”。
