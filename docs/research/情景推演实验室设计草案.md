# 情景推演实验室设计草案

## 文档定位

本文档用于规划 A股智研台未来的 `Scenario Lab / 情景推演室` 能力。

当前阶段只做研究设计，不实现代码，不引入新依赖，不改变现有 `run-daily`、`doctor` 与 `project_info` 功能。

## A股智研台未来 Scenario Lab 定位

未来的 `Scenario Lab / 情景推演室` 应定位为：

- 面向事件驱动研究的多智能体实验层
- 面向公告、政策、舆情与叙事传播的推演空间
- 面向人工复核与模拟盘验证的研究辅助工具

它不是价格预测器，也不是自动交易模块，而是“研究假设试验场”。

## 可接受输入

未来情景推演室可处理的输入包括：

- 上市公司公告
- 财报与业绩预告
- 新闻快讯与深度报道
- 政策文件与监管表态
- 行业事件
- 外围市场冲击
- 社交平台舆情

这些输入更适合被看作“种子事件”，用于推演市场参与者可能如何理解、传播与反应。

## 角色设计草案

为了更贴近 A 股市场，未来情景推演室可以使用以下角色：

- 散户情绪
- 游资短线
- 机构价值
- 量化资金
- 政策监管
- 媒体叙事
- 产业链专家
- 空头质疑
- 风险审查

这些角色的价值不在于谁“绝对正确”，而在于：

- 模拟不同资金与叙事视角
- 观察事件传播时的偏差与冲突
- 发现潜在分歧点与高风险路径

## 预期输出

未来 Scenario Lab 更适合输出以下研究结果：

- 乐观情景
- 中性情景
- 悲观情景
- 传播路径
- 风险触发条件
- 对模拟盘持仓的潜在影响
- 需要人工复核的建议

推荐输出格式应保持结构化，例如：

- 事件摘要
- 核心角色反应
- 三情景结论
- 关键分歧
- 风险触发器
- 人工复核点

## 与现有模块的关系

### 与 `run-daily` 的关系

`run-daily` 负责日常数据采集、基础信号与日报输出。

Scenario Lab 不替代 `run-daily`，而是建立在其上方：

- `run-daily` 提供基础数据和当日观察
- 情景推演室处理“某一事件发生后可能怎样扩散”

也就是说，一个负责“现实快照”，一个负责“未来路径假设”。

### 与 `doctor` 的关系

`doctor` 负责数据源与网络健康检查。

未来如果情景推演依赖外部材料或多源输入，那么：

- `doctor` 应继续作为运行前的前置检查
- 如果数据源异常，情景推演结论应降低可信度

### 与未来模拟盘的关系

情景推演室不直接生成买卖动作，但可以为模拟盘提供：

- 风险提示
- 情景影响说明
- 仓位观察建议

模拟盘则负责记录和验证，不负责把情景结果直接当作交易指令。

### 与 Agent 研究层的关系

未来 Agent 研究层偏向：

- 基本面
- 技术面
- 新闻面
- 风控审查

Scenario Lab 可以作为 Agent 研究层的上游实验模块之一：

- Agent 负责总结“当前怎么看”
- Scenario Lab 负责推演“接下来可能怎么演化”

### 与 OpenClaw 的关系

未来若接入 OpenClaw，其职责仍应是：

- 调度
- 汇总
- 监控
- 提醒

而不是承载情景推演内核。

也就是说：

- Scenario Lab 是研究模块
- OpenClaw 是调度与交互模块

## 安全边界

未来即使实现 Scenario Lab，也必须坚持以下边界：

- 不直接预测股价点位
- 不直接触发实盘交易
- 不自动下单
- 不绕过人工复核
- 不把单次推演结果视为交易信号

## 当前阶段不落地内容

本轮明确不落地：

- 不实现 Scenario Lab 代码
- 不实现多 Agent 社会模拟引擎
- 不引入 Node.js、Vue、Flask、Zep、OASIS、Docker 等依赖
- 不增加前后端结构
- 不接入视频中展示的 BTC / Polymarket 叙事实验

## 当前结论

对 A股智研台而言，情景推演室最有价值的方向不是“替代策略系统”，而是：

- 补充事件冲击研究层
- 帮助研究员理解叙事传播
- 为模拟盘和人工决策提供风险路径参考

因此它应被定义为长期研究实验模块，而不是当前版本的落地功能。
