# 历史信号变化摘要说明 (V0.3.1)

## 概述

从 V0.3.1 版本开始，A股智研台引入了“历史信号变化摘要”能力。该模块基于 V0.3.0 的 SQLite 本地历史库，通过对比最近两次成功的 `run-daily` 记录，自动识别并汇总信号变化、强度变化及数据风险项。

## 核心功能

1. **信号变化识别**：自动对比前后两次运行的 `signal` 字段（如 `neutral -> trend_up`）。
2. **强度变化识别**：识别 `signal_level` 的升降（如 `neutral -> positive`）。
3. **数据状态监控**：识别 `data_status` 的变化，特别是从 `ok` 变为异常状态。
4. **资产变动跟踪**：识别新加入的自选股或已移除的资产。
5. **风险项汇总**：提取所有 `data_status` 非 `ok` 的项（如 `fetch_failed`, `stale_data`）。

## 变化类型 (Change Types)

- `signal_changed`: 核心趋势信号发生变化。
- `level_changed`: 信号强度发生变化，但核心趋势未变。
- `data_status_changed`: 数据采集或校验状态发生变化。
- `new_asset`: 最新运行中新增的资产。
- `missing_asset`: 在上一轮运行中存在但本轮未采集的资产。
- `risk_status`: 识别为数据风险或质量问题的项。

## 使用方式

### 命令行查询
执行以下命令查看最新一轮运行相对于上一轮的变化：
```bash
python3 app.py changes
```

### 运行产物
每次 `run-daily` 成功后，如果存在上一轮记录，系统会自动在 `data/processed/` 目录下生成：
- `signal_changes.csv`：包含所有变化项的结构化明细。

## 技术实现

- **模块**：`app_core/analytics/history_summary.py`
- **逻辑**：采用内存 Map 对比算法，通过 `symbol` 或 `code` 作为唯一标识进行双向对比。
- **解耦**：摘要生成逻辑与数据库写入逻辑分离，确保即使没有历史记录，系统也能友好运行。

## 后续规划

1. **多周期对比**：支持与一周前、一月前的记录进行对比。
2. **Dashboard 视图**：在 GUI 中以卡片形式展示核心变化。
3. **AI 深度复盘**：将变化摘要作为上下文输入给 AI，生成更具洞察力的复盘文字。
