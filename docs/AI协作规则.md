# AI协作规则

## 目标

AI 主要用于提升开发效率、补全文档、整理结构、辅助排查问题，但不替代最终的人工判断。

## 协作原则

- 每轮任务先明确范围，再开始实现
- 优先做小步、可验证的改动
- 不在未确认边界时实现复杂功能
- 不生成越过安全边界的能力
- 研究阶段完成后，后续功能开发仍遵循最小闭环、外科手术式修改、不可跳跃式重构

## 代码规则

- 优先保持结构清晰
- 不引入不必要的复杂依赖
- 路径使用相对路径
- 重要配置放入 `config/`
- 敏感信息不写入仓库
- 项目名称、版本、开发者、版权和安全提醒等元信息统一放在 `app_core/project_info.py`
- Python 平台负责数据采集、数据存储、策略信号、模拟盘、风控和报告等底层核心能力
- OpenClaw 仅作为后续接入的本地 AI Agent 与自动化调度层，不写成底层交易核心
- 涉及第三方开源项目时，先研究、先文档化、先明确许可证边界，再决定是否需要自研实现。
- 严禁直接复制第三方源码，不复刻其 UI 布局、视觉风格、终端命令体系、快捷键或专有词汇。
- 当前阶段不引入 C++、Qt6、LangGraph、MCP、Backtrader、Redis、Node.js、Vue、Flask、Zep、OASIS、Docker 等重依赖，保持 A 股智研台的轻量化。
- 研究阶段完成后，后续功能开发仍遵循最小闭环、外科手术式修改、不可跳跃式重构。
- 多智能体情景推演只能作为研究规划对象，不得直接扩展为股价裸预测器、交易信号生成器或实盘执行模块。

## 文档规则

- README 保持与实际状态一致
- `docs/` 文档在每轮开发后同步更新
- 阶段目标、边界和风险要写清楚
- 开发者、维护者、版权品牌和版本信息变更时，要同步更新相关文档与输出入口
- 涉及 OpenClaw 时，要明确其职责是调度、汇总、解释、监控和交互，不与底层 Python 核心混淆
- 涉及第三方项目时，要明确该项目不属于本项目，并区分“架构启发”与“不可复制表达”

## 风险处理

- 遇到涉及真实交易、自动下单、平台绕过的需求时，应停止实现
- 遇到可能泄露敏感信息的操作时，应优先改为本地占位或示例方案
- 遇到 OpenClaw 相关需求时，不得直接扩展为交易执行核心或自动下单中枢
- 遇到第三方 UI、trade dress、终端命令、快捷键、商标相关内容时，应停止复制式实现，改为抽象总结与自有设计
- 遇到第三方项目演示中的收益展示、BTC/Polymarket 结果等内容时，不得将其表述为本项目可复用策略，应改为风险提示与边界说明
