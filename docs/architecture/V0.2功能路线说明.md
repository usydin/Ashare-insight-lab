# V0.2 功能路线说明

## 文档定位

本文档用于说明 A股智研台在 V0.2 阶段的功能边界、拆分建议和预期输出。

V0.2 的核心任务，是在不进入模拟盘、Agent、GUI 的前提下，把数据源与日报能力做厚、做稳、做得更可读。

## V0.2 的核心目标

V0.2 的重点是：

- 数据源与日报增强
- 不进入模拟盘
- 不进入 Agent 代码
- 不进入 GUI

也就是说，V0.2 仍然坚持最小闭环原则：

- 先把底层数据稳定性和输出质量打牢
- 不提前跳进更高层的复杂模块

## V0.2 建议拆分

### V0.2.1 watchlist 扩展与字段增强

目标：

- 扩展自选股配置能力
- 增加更多基础字段
- 提升 `daily_signals.csv` 的信息密度

可考虑方向：

- 股票名称
- 所属市场
- 行业标签占位
- 观察优先级
- 备注字段

本轮实际落点：

- 扩展 `watchlist` 字段：`industry`、`sector`、`board`、`tags`、`priority`
- 增加 `position_status`、`observe_reason`、`risk_note`、`data_source`、`note`
- 增加默认值标准化：`priority=P3`、`position_status=watch`、`data_source=akshare`
- 增强 `daily_signals.csv` 与 Markdown 日报字段

### V0.2.2 指数数据接入

目标：

- 增加主要 A 股指数观察
- 为个股日报提供大盘背景

本轮实际落点：

- 新增 `config/market_indices.json` 配置文件。
- 新增 `app_core/market_indices.py` 指数标准化模块。
- 新增 `app_core/data_sources/index_provider.py` 指数采集模块。
- 在 `run-daily` 中集成指数采集与趋势分析，先看大盘再看个股。
- 升级日报增加“市场指数观察”章节。

### V0.2.3 板块 / 行业基础数据

目标：

- 增加行业与板块层面的基础观察
- 为后续行业分析员和报告中心预留结构化输入

本轮实际落点：

- 新增 `config/sector_boards.json` 配置文件，涵盖 A 股代表性概念与行业板块。
- 新增 `app_core/sector_boards.py`，实现板块配置的标准化加载与过滤。
- 新增 `app_core/data_sources/sector_provider.py`，封装基于 AKShare/东方财富的板块历史数据采集。
- 在 `run-daily` 中集成板块分析，先看大盘，再看板块，最后看个股。
- 升级日报增加“行业/板块观察”章节。

### V0.2.4 UI 规划 (本阶段冻结)

目标：

- 明确未来 UI 演进路线
- 确定产品原型与页面布局

本轮实际落点：

- 确立 Tauri + React + Python sidecar 技术架构。
- 完成 Dashboard、市场、行业、自选、报告等核心页面规划。
- 绘制 ASCII 布局草图，确立现代化 macOS 终端气质。
- 明确三项目（FinceptTerminal/TradingAgents/MiroFish）思想落地路径。

### V0.2.5 日报结构升级

目标：

- 提高日报可读性
- 从“简单结果输出”升级到“更接近研究观察”

可考虑方向：

- 增加指数观察段
- 增加行业观察段
- 增加数据源健康摘要段
- 增加重点标的观察段

### V0.2.6 数据质量检查

目标：

- 在 `run-daily` 输出中补充基础质量提示
- 让用户知道当日数据是否完整、是否存在明显缺口

可考虑方向：

- 缺失值提示
- 更新日期检查
- 单只股票抓取失败计数
- 当日整体数据质量摘要

## V0.2 的输出

V0.2 预期输出包括：

- 更丰富的 `daily_signals.csv`
- 更可读的每日观察报告
- 数据源健康状态摘要
- 自选股、指数、行业板块初步观察

这些输出仍然应保持：

- 本地优先
- 结构化优先
- Markdown 友好
- 为后续 Agent 和终端工作台预留接口

## V0.2 明确不做

V0.2 当前明确不做：

- 不做模拟盘账本
- 不做 AI Agent
- 不做 GUI
- 不做自动交易

同时也不做：

- 不接券商接口
- 不实现 OpenClaw
- 不实现 Scenario Lab
- 不引入新依赖

## 为什么 V0.2 要这样收敛

原因很明确：

1. `run-daily` 和 `doctor` 已经形成基础骨架
2. 三个开源项目研究已经完成，长期方向已清晰
3. 当前最需要的是让数据与报告层更扎实
4. 如果过早进入模拟盘、Agent、GUI，会打破最小闭环节奏

## 当前结论

V0.2 应被视为“数据与日报增强阶段”，不是“功能横向扩张阶段”。

只要 V0.2 做好以下三件事，就已经成功：

- 数据更稳
- 输出更多
- 日报更像研究报告
