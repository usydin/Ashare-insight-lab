# 开发计划

## V0.7 阶段目标：Data Source Manager / 数据源管理器与本地缓存兜底

### 第 1 步：统一数据源抽象与主数据源管理 (V0.7.0)

- 新增 `app_core/data_sources/base.py`，定义数据源能力、请求与结果结构。
- 新增 `app_core/data_sources/source_status.py`，定义健康状态与健康记录。
- 新增 `app_core/data_sources/manager.py`，统一注册主数据源并返回标准化 `DataSourceResult`。
- 当前只注册 `akshare`，保持真实采集链路稳定。
- 在 `config/settings.json` 中增加 `data_sources` 配置段。
- 将 `doctor` / `check-data-source` 轻量接入 manager，显示 `primary_source`、`fallback_order`、`registered_sources`、`fallback_enabled`。
- 预留 Tushare / BaoStock / 本地缓存兜底接口，但本阶段不真实接入。

### 第 2 步：Local Cache Fallback / 本地缓存兜底 (V0.7.1)

- 新增 `app_core/data_sources/local_cache_provider.py`，读取 `data/raw/{symbol}_daily_raw.csv` 作为降级数据源。
- 扩展 `DataSourceManager` 支持 `akshare -> local_cache` fallback 顺序与 `fallback_used` 标记。
- 为缓存兜底结果增加 `cache_fallback` / `stale_cache` 状态，明确说明在线数据源失败。
- 在 `doctor` / `check-data-source` 中增加 local cache 配置、缓存可用性与兜底状态展示。
- 谨慎接入 `run-daily` 主链路，保证无缓存时仍保持 `fetch_failed` 语义不变。
- 明确本地缓存不是实时行情，仅用于降级兜底；后续版本再评估 Tushare / BaoStock。

### 第 3 步：增强前端 UI 数据源状态呈现 (V0.7.2) - 当前已完成

- 在 Dashboard 数据健康面板中增加 `cache_fallback` / `stale_cache` 统计。
- 在 TopBar 增加数据源全局状态动态提示。
- 在市场指数、行业板块、自选股列表表格中增加数据源状态 Badge。
- 在报告中心摘要区增加缓存兜底说明。
- 在 `styles.css` 中定义统一样式。

## 迭代原则

- 每轮只推进一个清晰目标
- 每轮开发后都要求可运行、可验证
- 优先小步提交，避免一次性堆积复杂功能
- 不把 OpenClaw 设计成底层交易核心，底层核心持续由 Python 平台承担
- 第三方开源项目先研究文档化，再决定是否需要自研，不直接复制源码
- 研究阶段完成后，后续功能开发仍遵循最小闭环、外科手术式修改、不可跳跃式重构
