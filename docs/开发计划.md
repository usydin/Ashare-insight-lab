# 开发计划

## V0.1 阶段目标

### 第 1 步：骨架修复与初始化

- 完成 README
- 完成 `docs` 文档
- 完成最小入口程序
- 检查配置文件合法性

### 第 2 步：run-daily 设计

- 明确每日执行流程
- 明确输入输出目录
- 设计日志与异常处理方式
- 设计日报生成顺序
- 预留 OpenClaw 后续接入的任务触发与调度边界

### 第 3 步：数据与策略

- 接入本地数据采集
- 建立基础数据清洗流程
- 编写首批策略信号模块

### 第 4 步：模拟盘

- 定义持仓、现金、成交、费用规则
- 完成本地记账结构
- 输出每日模拟盘摘要

### 第 5 步：报告

- 输出日报
- 输出周报或复盘报告
- 沉淀策略观察结论

### 第 5.1 步：数据源健康检查 (V0.1.3)

- 增加 `check-data-source` / `doctor` 命令
- 检查代理环境变量与脱敏展示
- 检查 `requests` / `akshare` 依赖可用性
- 检查东方财富基础 URL 连通性
- 检查示例股票采集状态
- 输出 Markdown 健康检查报告

### 第 5.2 步：TradingAgents 源码学习与适配规划 (V0.1.4)

- 研究 TradingAgents 架构：Agents / Graph / Dataflows / LLM Clients
- 制定多智能体投研架构借鉴方案
- 明确 Apache-2.0 第三方代码使用边界
- 规划 A 股智研台 Agent 路线图 (V0.2 - V0.7)

### 第 5.3 步：FinceptTerminal 产品形态与终端架构研究 (V0.1.5)

- 研究 FinceptTerminal 的 screens / services / storage / ui / python 模块组织。
- 提炼金融终端产品形态、DataHub、数据连接器与工作区思路。
- 明确 AGPL-3.0 与商业许可边界。
- 形成 5 份核心研究文档并规划长期终端化路线图。
- 重点：将模块化工作台（Screens）与统一数据中心（DataHub）思想融入长期规划。

### 第 5.4 步：MiroFish 多智能体情景推演研究 (V0.1.6)

- 研究 MiroFish 的 graph / simulation / report 三类接口职责。
- 研究 graph_builder、simulation_manager、report_agent 等服务层组织方式。
- 总结五阶段流程：Graph Building、Environment Setup、Simulation、Report Generation、Deep Interaction。
- 规划 A 股智研台未来 `Scenario Lab / 情景推演室` 定位与使用边界。
- 明确情景推演只用于研究参考，不直接预测股价，不直接触发实盘交易。

### 第 5.5 步：三项目融合路线总览与长期架构收敛 (V0.1.7)

- 融合 TradingAgents、FinceptTerminal、MiroFish 三个项目的研究结论。
- 形成 A股智研台自己的长期架构总览、模块分层与职责边界。
- 制定三项目融合路线图，明确哪些思想可借鉴，哪些实现未来可自研。
- 明确未来 UI 与金融终端化技术路线（PySide6 + Python Core）。
- 规划 V0.2 功能路线，下一阶段进入数据源与日报增强。

### 第 6 步：OpenClaw 接入规划

- 明确 OpenClaw 作为本地 AI Agent 与自动化调度层的边界
- 由 OpenClaw 定时触发数据采集任务
- 由 OpenClaw 汇总 A 股、美股、港股和全球宏观信息
- 由 OpenClaw 读取本地策略信号和模拟盘结果
- 由 OpenClaw 生成盘前、盘后、周报和复盘摘要
- 由 OpenClaw 对交易建议进行风险解释和反方审查
- 由 OpenClaw 监控数据源异常、任务失败和模拟盘异常回撤
- 由 OpenClaw 作为本地 AI 交互入口

## 长期终端化方向

- 借鉴 FinceptTerminal 的页面层与服务层解耦思路，规划未来工作台模块
- 逐步形成数据源健康中心、报告中心、自选股中心、风控中心、模拟盘账户、Agent 工作台
- 长期研究轻量 GUI 路线，可考虑 `PySide6` 或 `Flet`，但当前不实现
- 长期研究数据源注册表与 DataHub 雏形，但当前不实现
- 不复刻第三方界面、命令体系、快捷键与 trade dress

## 长期研究扩展方向

- 借鉴 TradingAgents 的多角色研究流程，规划未来 Agent 研究层
- 借鉴 MiroFish 的多智能体社会模拟思路，规划未来 `Scenario Lab / 情景推演室`
- 情景推演优先用于事件冲击、舆情扩散、政策影响与叙事传播研究
- 情景推演结果必须经过模拟盘与人工复核，不能直接当作交易信号

## 下一阶段重点

下一阶段正式进入 `V0.2 数据源与日报增强`，优先级如下：

1. 扩展 watchlist 与结构化字段
2. 增加指数数据接入
3. 增加行业 / 板块基础数据
4. 升级日报结构和健康状态摘要
5. 补充数据质量检查与 fallback 设计草案

## V0.2.1 当前落点

V0.2 的第一步聚焦：

- 扩展 `config/watchlist.json` 字段
- 增强 `daily_signals.csv` 元信息字段
- 提升日报中的自选股可读性
- 保持失败兜底逻辑不变

本步明确不做：

- 不做模拟盘
- 不做 AI Agent
- 不做 GUI
- 不做 OpenClaw
- 不做实盘交易

## 迭代原则

- 每轮只推进一个清晰目标
- 每轮开发后都要求可运行、可验证
- 优先小步提交，避免一次性堆积复杂功能
- 不把 OpenClaw 设计成底层交易核心，底层核心持续由 Python 平台承担
- 第三方开源项目先研究文档化，再决定是否需要自研，不直接复制源码
- 研究阶段完成后，后续功能开发仍遵循最小闭环、外科手术式修改、不可跳跃式重构
