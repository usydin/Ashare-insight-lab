# 开发计划

## V0.1 阶段目标

### 第 1 步：骨架修复与初始化

- 完成 README
- 完成 `docs` 文档
- 完成最小入口程序
- 检查配置文件合法性

### 第 2 步：run-daily 设计

- 明确每日执行流程
- 明确输入输出目录
- 设计日志与异常处理方式
- 设计日报生成顺序
- 预留 OpenClaw 后续接入的任务触发与调度边界

### 第 3 步：数据与策略

- 接入本地数据采集
- 建立基础数据清洗流程
- 编写首批策略信号模块

### 第 4 步：模拟盘

- 定义持仓、现金、成交、费用规则
- 完成本地记账结构
- 输出每日模拟盘摘要

### 第 5 步：报告

- 输出日报
- 输出周报或复盘报告
- 沉淀策略观察结论

### 第 6 步：OpenClaw 接入规划

- 明确 OpenClaw 作为本地 AI Agent 与自动化调度层的边界
- 由 OpenClaw 定时触发数据采集任务
- 由 OpenClaw 汇总 A 股、美股、港股和全球宏观信息
- 由 OpenClaw 读取本地策略信号和模拟盘结果
- 由 OpenClaw 生成盘前、盘后、周报和复盘摘要
- 由 OpenClaw 对交易建议进行风险解释和反方审查
- 由 OpenClaw 监控数据源异常、任务失败和模拟盘异常回撤
- 由 OpenClaw 作为本地 AI 交互入口

## 迭代原则

- 每轮只推进一个清晰目标
- 每轮开发后都要求可运行、可验证
- 优先小步提交，避免一次性堆积复杂功能
- 不把 OpenClaw 设计成底层交易核心，底层核心持续由 Python 平台承担
